# C++ 内存四区笔记：栈区的坑 & 堆区的 new/delete

整理自课堂纪要，代码都自己敲过。建议别只看，跟着跑一遍。

## 0. 先用一张表把栈和堆分开

| | 栈区 stack | 堆区 heap |
|---|---|---|
| 谁开辟、谁释放 | 编译器自动 | 程序员手动（new / delete） |
| 放什么 | 函数参数、局部变量 | new 出来的数据 |
| 生命周期 | 函数执行完就回收 | 不 delete 就一直活着，程序结束系统才收 |
| 地址能不能往外传 | 不能，返回局部变量地址是错的 | 能，堆上的地址可以返回 |
| 常见事故 | 返回局部变量地址、野指针 | 忘 delete、delete 后继续用、数组漏 [] |

内存四区里还有全局区和代码区，这节课主要讲栈和堆，先把这两个弄明白。

## 1. 栈区：编译器说了算

栈区放的是函数参数和局部变量。什么时候开辟、什么时候释放，都是编译器安排好的，程序员插不上手。函数一执行完，这块栈内存就回收了。

所以有个铁律：**不要返回局部变量的地址。**

先看反例：

```cpp
#include <iostream>
using namespace std;

int* func()
{
    int a = 10;      // a 是局部变量，在栈上
    return &a;       // 把 a 的地址返回出去 —— 错的
}

int main()
{
    int* p = func();
    cout << *p << endl;   // 第一次：10
    cout << *p << endl;   // 第二次：乱码 / 崩溃
    return 0;
}
```

现象很坑：第一次打印居然是 10。课上给的解释是编译器"保留"了一次，怕你误操作。但第二次、第三次就原形毕露了，输出乱码或者直接崩。

本质是这块栈内存刚被回收、还没被别的函数覆盖，所以侥幸还是 10。这是未定义行为，今天对不代表明天对，换个编译器、中间加个打印就可能变。**测试通过 ≠ 代码正确。**

正确做法：要往外传数据，就在堆上开，或者用返回值 / 引用参数。

编译的时候 MSVC 会给个警告 C4172（返回局部变量或临时变量的地址），看到别忽略。

## 2. 堆区：new 和 delete 都得自己写

堆区的数据由程序员自己开辟、自己释放。new 出来的东西，只要你不 delete，它在程序运行期间就一直活着，直到整个程序结束系统才统一回收。

### 2.1 new 一个变量

```cpp
int* p = new int(10);   // 在堆上开一个 int，初始值 10
cout << *p << endl;     // 10

delete p;               // 用完手动释放
p = nullptr;            // 好习惯：置空，防止后面误用
```

几个要点：

- `new int(10)` 小括号里是**初始值**，不是长度。
- new 返回的是对应类型的指针，`new int` 返回 `int*`，得用同类型指针接。
- 指针变量 `p` 自己是个局部变量，住在**栈**上；它存的地址（比如 0x0001）指向**堆**上那块 int。这是初学最容易绕晕的地方：p 在栈，*p 在堆。

### 2.2 delete 之后别再碰

```cpp
int* p = new int(10);
delete p;
cout << *p << endl;   // 危险：读取访问权限冲突
```

释放之后那块内存就不归你了，再去解引用，Debug 下常见的结果就是"读取访问权限冲突"（0xC0000005），程序直接挂掉。

注意不是每次都会立刻崩，有时还能读出旧值，这同样是未定义行为，纯属运气。delete 完把指针置空，至少能让自己少犯迷糊。

## 3. 堆区数组：中括号是灵魂

### 3.1 开数组

```cpp
int* arr = new int[10];   // 10 个元素的数组，中括号是长度

for (int i = 0; i < 10; i++)
    arr[i] = 100 + i;

for (int i = 0; i < 10; i++)
    cout << arr[i] << endl;   // 100 ~ 109
```

- `new int[10]` 返回的是这段连续内存的**首地址**，用起来和栈上的数组一样，`arr[i]` 读写。
- 别和 `new int(10)` 搞混：小括号是"一个 int，初值 10"，中括号是"10 个 int"。差一个符号，结果差很多。

### 3.2 释放数组必须带 []

```cpp
delete[] arr;   // 对
// delete arr;  // 错
```

`delete[]` 里的方括号是在告诉编译器：这是一段连续空间，要整段释放。

要是写成 `delete arr`，编译器只把首元素那块内存还回去，后面 9 个元素就泄漏了，而且后续再访问这段内存，行为是未定义的。堆数组配 `delete[]`，单变量配 `delete`，别配错。

## 4. 踩坑记录（都是课上强调过的）

1. **返回局部变量地址**：第一次打印对，第二次乱码。测试过了也别当真，本质是未定义行为。
2. **delete 之后继续用**：悬垂指针，Debug 下容易报读取访问权限冲突。
3. **释放数组漏了 []**：`delete arr` 只放首元素，其余泄漏。
4. **new[] 用 delete 释放 / new 用 delete[] 释放**：不匹配，行为未定义。
5. **忘了 delete**：程序跑着跑着内存一直涨，短时间看不出来，长时间跑就出问题。
6. **`new int[10]` 写成 `new int(10)`**：以为开了数组，其实只开了一个值为 10 的 int。

写完 new，顺手就把对应的 delete 想好写在哪，能少一半的坑。

## 5. 口诀

- 栈：编译器管，地址别外传。
- 堆：自己管，new 完记得 delete。
- 小括号放值，中括号放长度；delete 单变量，delete[] 数组。
