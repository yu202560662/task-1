

本次讲解C++函数核心语法。默认参数需从右向左连续设置，且声明与实现只能一处定义；占位参数现阶段仅作铺垫。函数重载要求同名函数参数类型、个数或顺序不同，返回值差异无效。重点提示两个易错点：引用加const可区分重载版本；重载函数若含默认参数可能引发调用二义性，建议避免混用。




## 默认参数语法与传参优先级

- **默认参数基本语法**
  - 在C++中声明函数时，可在形参列表中通过等号为形参指定默认值，如`int b = 20`
  - 函数体代码编写方式与普通函数一致，默认值仅影响调用时的参数传递行为
- **实参与默认值的优先级**
  - 调用函数时若传入实参，则使用传入的实参值进行计算
  - 若未传入对应位置的实参，则自动使用声明时设定的默认值
  - 示例演示：函数`fnc(a, b=20, c=30)`，调用`fnc(10)`时b取20、c取30，结果为60；调用`fnc(10, 30)`时b取传入的30、c取默认30，结果为70
- **默认参数的位置约束**
  - 若某个位置的形参已设置默认值，则从该位置起从左到右的所有后续形参都必须设置默认值
  - 违反此规则编译器将报错，提示默认参数不在形参列表末尾
  - 默认参数左侧的形参可以不设默认值，不影响语法合法性

## 默认参数在声明与实现中的约束

- **声明与实现只能一处设置默认值**
  - 函数的声明和实现可以分离，但默认参数只能在其中一处出现，不可同时设置
  - 若声明和实现均设置了默认参数，编译器报"重定义的默认参数"错误
- **两种合法写法验证**
  - 仅在声明中设置默认值、实现中不设：编译通过，调用时按声明的默认值执行
  - 仅在实现中设置默认值、声明中不设：编译通过，调用时按实现的默认值执行
  - 讲者强调实际开发中推荐在声明中设置默认值，以便调用方可见

## 占位参数的定义与教学定位

- **占位参数语法形式**
  - 在形参列表中只写数据类型而不写变量名，如`int`，即为占位参数
  - 调用函数时必须传入对应类型的实参，否则编译报错
  - 占位参数也可以设置默认值，如`int = 10`，此时调用时可不传该位置实参
- **现阶段学习定位**
  - 占位参数在当前阶段的函数体中无法被引用和使用，因为缺少变量名
  - 讲者明确说明该技术点是为后续课程内容做铺垫，现阶段只需知道其存在即可
  - 占位参数配合默认参数后实用性进一步降低，但属于C++语法合法组成部分

## 函数重载的三个必要条件

- **同一作用域**
  - 发生重载的多个函数必须处于同一作用域下，如均为全局函数或同一类成员函数
  - 不同作用域中的同名函数不构成重载关系
- **函数名相同**
  - 重载的核心特征是多个函数共用同一个函数名
  - 编译器根据调用时传入的实参匹配具体调用哪个版本的函数
- **参数列表不同**
  - 参数个数不同：如一个版本无参，另一个版本有一个或多个参数
  - 参数类型不同：如一个版本参数为`int`，另一个为`double`
  - 参数顺序不同：如一个版本为`(int, double)`，另一个为`(double, int)`
  - 以上三种差异任一满足即可构成重载，编译器可根据实参准确区分调用目标

## 返回值类型不可作为重载条件

- **仅返回值不同不构成重载**
  - 两个函数名相同、参数列表完全相同，仅返回值类型不同（如一个返回`void`、一个返回`int`），编译器报"无法重载仅按返回类型区分的函数"错误
- **调用歧义是根本原因**
  - 调用函数时可以忽略返回值，如直接写`func(10);`而不接收返回结果
  - 此时编译器无法根据调用语句判断应调用哪个版本，产生二义性
  - 讲者以示例说明：无论返回`void`还是`int`的版本，`func(10);`均可合法调用，故返回值不能作为区分依据

## 引用加const作为重载条件的区分机制

- **const引用与非const引用可构成重载**
  - `void func(int &a)`与`void func(const int &a)`参数类型不同，可作为重载条件
  - 两者在同一作用域下函数名相同，编译器可根据实参性质选择匹配版本
- **变量与字面量的匹配差异**
  - 传入普通变量（如`int a = 10`）时，匹配非const引用版本，因为变量可读可写，绑定非const引用合法
  - 传入字面量（如直接传`10`）时，只能匹配const引用版本
    - 非const引用不能绑定字面量，因为字面量存储在常量区，绑定非const引用语法不合法
    - const引用绑定时，编译器会创建临时空间存放字面量，让const引用指向该临时空间，语法合法
  - 因此传入字面量时不存在二义性，编译器唯一匹配const引用版本

## 函数重载遇默认参数的二义性风险

- **二义性触发场景**
  - 当重载函数中某个版本带有默认参数时，可能出现同一调用语句同时匹配多个版本的情况
  - 示例：`func2(int a, int b = 10)`与`func2(int a)`构成重载（参数个数不同），调用`func2(10)`时两个版本均可匹配，编译器报二义性错误
- **规避方式与注意事项**
  - 讲者建议在设计重载函数时尽量避免使用默认参数，以防止二义性问题
  - 若传入实参个数能明确区分版本（如传两个参数必定匹配双参数版本），则不会产生二义性
  - 该问题属于语法层面的坑，需在编码时主动识别并规避，而非依赖编译器自动解决
