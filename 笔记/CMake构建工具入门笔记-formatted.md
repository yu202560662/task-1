# 一、软件构建工具概述

* **软件构建是软件开发中必不可少的步骤**，用于全自动完成代码的编译、链接、打包过程，并管理不同组件及第三方库的关联。
* 不同构建工具各有擅长的领域：VS 中做 C++ 开发用 MSBuild，Android Studio 写移动端用 Gradle 等。
* 还有更复杂万能的构建系统（如 Bazel），试图用单个工具完成各种语言在不同环境下的构建。

# 二、CMake 简介

* 被广泛使用、开源免费、完全跨平台的构建工具，**专门用于 C 和 C++ 程序的构建**。
* 可在不同平台上编译运行软件，无需手动配置 VS 或 Xcode 工程。

# 三、CMake 安装

* 可在官网下载安装包，或使用操作系统自带的包管理工具安装。
* 若找不到命令，需手动配置安装路径到 `PATH` 环境变量。
* **需确保计算机上有 C/C++ 编译工具链**（Windows 下如 MSVC 工具链或 VS，Linux 下安装 GCC 等），因为 CMake 自身不带编译工具。

# 四、CMake 基本用法（单文件工程）

* 在项目根目录创建 `CMakeLists.txt` 文件，**三行核心代码必不可少**：

  1. 第 1 行：指定构建项目所需的最低 CMake 版本
  2. 第 2 行：指定工程名字（输出的可执行文件同名）
  3. 第 3 行：声明项目需构建可执行文件，由 `main.cpp` 编译而成

* **配置（Configuration）**：根据 `CMakeLists.txt` 生成目标平台下的原生工程文件（Windows 下 VS 工程、Linux 下 Makefile 等）。

* **构建（Build）**：使用快捷键 F7 或在菜单中运行 `CMake.Build` 命令，成功后输出可执行文件。

* 配置和构建操作都有对应的命令行指令，便于在服务器上做持续集成、自动化编译和测试。

# 五、复杂工程配置（多文件+第三方库）

* 前两行与简单工程相同（最低版本和工程名）。
* **`find_package` 命令**：在计算机中寻找符合要求的第三方库，需事先安装好且库支持 CMake 构建；第 1 个参数是库名，`REQUIRED` 表示该库是必须的，未安装会直接报错。
* **`file(GLOB ...)`**：通过通配符匹配所有源文件，存入变量 `source file` 中。
* **`add_executable`**：构建可执行文件，第 1 个参数是工程文件名（`CMake project name` 宏自动替换为工程名），第 2 个参数是匹配的所有源文件。
* **链接库操作**：项目用到第三方库必须链接，否则会遇到经典的"符号无法解析"错误。
* **`targetcompilefeatures`**：项目用到 C++17 以上语法时，需打开对 C++17 的支持。
* **`addcustomcommand`（POST\_BUILD）**：编译之后要执行的操作，例如调用 CMake 命令将根目录下 `assets` 文件夹拷贝到输出路径，避免手动复制文件。

# 六、C++ 第三方库安装

* CMake 只是构建工具，**不包含库安装和管理**。
* 常见安装方式：直接下载库源文件，手动构建并指定 CMake 库路径。
* Linux 和 Mac 可直接用包管理工具安装，但每装一个库需执行许多繁琐步骤，不同平台配置过程不同。
* **推荐：微软开源工具 vcpkg**——跨平台的 C++ 库管理工具（类似 Python 的 pip）。

  * 先调用 `vcpkg install` 安装第三方库，再在 CMake 构建时指定 vcpkg 工具链即可。
  * 命令行只需额外指定一个参数；用 VS 插件则在设置中添加路径。

# 七、总结与建议

* CMake 非常灵活但也非常复杂，**最好边用边学**，亲自创建工程并引入外部关联，尝试将项目顺利构建起来。
* 遇到问题可通过阅读文档或搜索引擎寻找答案。
* **CMake 本身也是一种编程语言**，可实现基本程序逻辑（循环、条件分支等），典型应用是根据工程配置选择性编译部分源代码（如某些功能只在测试版本开启）。
* CMake 本质是**定义各目标之间的关联**（可执行文件、动态库、资源文件由哪些文件编译、用到哪些外部关联）。
* 还可添加单元测试、创建安装包、将工程拆分成若干子目录，便于大型项目管理。
